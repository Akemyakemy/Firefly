# 先说结论

> 这个**同步阻塞队列（SyncQueue）** 属于《计算机系统》/《操作系统》课程里 **进程/线程同步、条件变量、生产者消费者模型** 的实战内容，也是后端、服务器、操作系统实验最经典的代码。 你现在现状：懂C++基础，**面向对象0基础、线程锁0基础**，我从头讲，避开复杂术语，一段一段拆开。

> 先纠正代码里的笔误（不影响理解，编译要改） `std:mutex` → `std::mutex`；`interrupt_flg` 变量名前后不一致：成员变量叫`interrupt_flag`，代码里写成`interrupt_flg`，统一名字。

## 1. 这个队列是用来干嘛的？

普通`std::queue`（C++自带队列）**不是线程安全**。 如果多个线程同时读写普通queue：

- 线程A放元素（push）
- 线程B拿元素（pop） 两个线程同时操作同一个queue，内存数据会乱掉、程序崩溃，这叫**竞态条件（race condition）**。

这个`SyncQueue` = **加了保护的线程安全队列**，典型场景【生产者-消费者模型】

- 生产者线程：往队列丢任务（`push`）
- 消费者线程：从队列拿任务（`pop`） 特性：

1. 队列满的时候，生产者`push()`会**卡住等待**，直到队列有空位置；
2. 队列空的时候，消费者`pop()`会**卡住等待**，直到有新元素进来；
3. 支持中断：调用`interrupt()`，所有正在等待的线程立刻退出，用于关闭线程、安全退出程序。

## 2. 先看用到的3个核心新概念（重中之重）

### ① std::mutex 互斥锁

mutex = mutual exclusion，**互斥锁**

> 规则：同一时刻，**最多只能有1个线程拿到锁**。 拿到锁 → 可以操作队列；没拿到锁 → 线程卡在lock这里，原地等待，等别人释放锁。

```C++
std::lock_guard<std::mutex> lock(queue_mutex);
```

`lock_guard`：**自动锁**。

- 执行这一行：自动加锁；
- 离开当前`{}`代码块（大括号范围结束），**自动解锁**，不用手动unlock，防止忘记解锁造成死锁。

`std::unique_lock<std::mutex>`：也是锁，比lock_guard灵活，**支持把锁临时释放**，专门配合条件变量使用，`condition_variable`只能搭配unique_lock。

> 一句话记锁：锁用来保证，**修改/读取队列的代码，同一时间只有一个线程在跑**。

### ② std::condition_variable 条件变量

条件变量：让线程**主动休眠等待某个条件成立**，别人满足条件后唤醒它。 这里两个条件变量：

1. `queue_not_full`：队列**不满**的信号。队列满了，生产者就在这里休眠；当消费者拿走元素，队列有空位，通知唤醒等待的生产者。
2. `queue_not_empty`：队列**不为空**的信号。队列空了，消费者就在这里休眠；生产者放入元素后，通知唤醒等待的消费者。

`cv.wait(lock, 谓词lambda)` 这个是最关键的一行：

```C++
queue_not_full.wait(lock,[this](){
    return interrupt_flg || !full();
});
```

wait做的事情：

1. 检查后面lambda表达式（条件）；

2. 如果条件不成立：**释放锁，线程休眠**，不再占用CPU；

3. 等到别的线程调用`notify_one()`/`notify_all()`唤醒这个线程；

4. 唤醒后

   重新拿到锁

   ，再次检查lambda条件；

   > ⚠️为什么要二次检查？存在**虚假唤醒**：线程可能无缘无故被唤醒，这时候条件依然不满足，所以必须循环判断条件。

`notify_one()`：唤醒**一个**正在等待该条件变量的线程。 `notify_all()`：唤醒**所有**等待这个条件变量的线程（interrupt中断的时候用这个，一次性全部唤醒）。

### ③ std::optional

C++17的类型。`std::optional<T>`代表**可能有值，也可能没有值**。 pop拿元素的时候，如果队列被中断，拿不出元素，返回`std::nullopt`（空）；拿到元素则包装返回T。 用来区分：是**正常取出元素**，还是**队列中断、没有元素可取**。

## 3. 逐段拆解代码

```C++
template <typename T>
struct SyncQueue {
```

模板struct，可以存放任意类型T，既能存int，也能存任务对象。struct在这里和class很像，默认public。

```C++
 public:
  SyncQueue(size_t capacity) : capacity(capacity), interrupt_flag(false) {}
  SyncQueue() = delete;
  SyncQueue(const SyncQueue<T>&) = delete;
  SyncQueue& operator=(const SyncQueue<T>&) = delete;
```

- 构造函数：创建队列，设置最大容量capacity，中断标记初始false；
- `SyncQueue()=delete`：删除无参构造，**不允许创建没有容量限制的队列**；
- 拷贝构造、赋值`=delete`：**禁止拷贝整个同步队列**。同步队列里面有锁，锁不能复制，队列不能拷贝，否则锁会乱。

```C++
  ~SyncQueue() {
    interrupt();
  }
```

析构函数：队列销毁的时候自动调用`interrupt()`，唤醒所有阻塞等待的线程，防止线程卡死。

```C++
  void interrupt() {
    std::lock_guard<std::mutex> lock(queue_mutex);
    interrupt_flg=true;
    queue_not_full.notify_all();
    queue_not_empty.notify_all();
  }
```

中断函数：上锁，把中断标记置true，**唤醒所有等待的生产者、消费者线程**。 所有wait里面的lambda检测到`interrupt_flg=true`，wait直接返回，push/pop会退出，不再阻塞。

> 用途：程序退出前调用，让所有卡在push/pop的线程安全退出，不会死等。

```C++
  bool try_push(const T& event) {
    std::lock_guard<std::mutex> lock(queue_mutex);
    if(full() || interrupt_flg) return false;
    queue.push(event);
    queue_not_empty.notify_one();
    return true;
  }
```

`try_push`：**非阻塞入队**，不等待。 拿到锁，判断：队列满 或者 队列被中断 → 直接return false，不等待。 能入队：push元素，发通知唤醒**一个**等待的消费者线程，返回true。

```C++
  std::optional<T> try_pop() {
    std::lock_guard<std::mutex> lock(queue_mutex);
    if(empty() || interrupt_flg) return std::nullopt;
    T val=queue.front();
    queue.pop();
    queue_not_full.notify_one();
    return val;
  }
```

`try_pop`：**非阻塞出队**，不等待。 队列为空 / 中断 → 返回空`nullopt`； 有元素：取出队首，弹出队列，通知生产者队列有空位了。

```C++
  bool push(const T& element) {
    std::unique_lock<std::mutex> lock(queue_mutex);
    queue_not_full.wait(lock,[this](){
        return interrupt_flg || !full();
    });
    if(interrupt_flg) return false;
    queue.push(element);
    queue_not_empty.notify_one();
    return true;
  }
```

**阻塞push**（重点）

1. unique_lock获取锁；
2. wait等待：条件是【中断标记打开 或者 队列不满】；
   - 如果队列满，并且没有中断：释放锁，线程休眠，等消费者拿元素；
3. wait返回之后，**再次上锁**，先判断是不是中断；中断直接return false；
4. 队列不满，把元素放进queue，通知一个等待的消费者。

```C++
  std::optional<T> pop() {
    std::unique_lock<std:mutex> lock(queue_mutex);
    queue_not_empty.wait(lock,[this](){
        return interrupt_flg || !empty();
    });
    if(interrupt_flg) return std::nullopt;
    T val=queue.front();
    queue.pop();
    queue_not_full.notify_one();
    return val;
  }
```

**阻塞pop（重点）** 队列空并且没有中断 → 线程休眠，等生产者放入元素。 一旦被唤醒，先判断中断标记，如果被中断返回空。 拿到元素之后，通知生产者：队列腾出位置了。

```C++
  size_t length() {
    std::lock_guard<std:mutex> lock(queue_mutex);
    return queue.size();
  }
  bool full() {
    return queue.size()>=capacity;
  }
  bool empty() {
    return queue.empty();
  }
  void clear() {
    std::lock_guard<std::mutex> lock(queue_mutex);
    while(queue.size()) queue.pop();
  }
```

获取长度、判满判空、清空队列。**所有读取/修改队列操作都要上锁！**

> 注意：full/empty成员函数**这里有bug！** `full()`、`empty()`没有上锁！多线程调用`full()`的时候，别的线程可能同时修改queue.size()，会出现数据竞争。 修正方案：把full/empty改成私有，或者调用前加锁，不要直接暴露无锁的full/empty给外部。

```c++
 private:
  size_t capacity;
  std::atomic<bool> interrupt_flag;
  std::queue<T> queue;
  std::mutex queue_mutex;
  std::condition_variable queue_not_full;
  std::condition_variable queue_not_empty;
};
```

私有成员：

- capacity：队列最大容量（有界队列）

- ```C++
  std::atomic<bool> interrupt_flag
  ```

  ：原子布尔变量。原子变量不用mutex保护，多线程读写不会出现数据错乱。

  > 这里设计：interrupt_flag是原子变量，但是在锁保护的临界区里修改，更稳妥。

- queue：底层普通std::queue，存储数据

- queue_mutex：互斥锁，保护queue

- 两个条件变量，负责休眠唤醒线程

## 4. 生产者消费者示例（可以直接跑，理解怎么用）

```C++
#include <iostream>
#include <queue>
#include <mutex>
#include <condition_variable>
#include <optional>
#include <thread>

template <typename T>
struct SyncQueue {
 public:
  SyncQueue(size_t capacity) : capacity(capacity), interrupt_flag(false) {}
  SyncQueue() = delete;
  SyncQueue(const SyncQueue<T>&) = delete;
  SyncQueue& operator=(const SyncQueue<T>&) = delete;
  ~SyncQueue() {
    interrupt();
  }
  void interrupt() {
    std::lock_guard<std::mutex> lock(queue_mutex);
    interrupt_flag = true;
    queue_not_full.notify_all();
    queue_not_empty.notify_all();
  }
  bool try_push(const T& event) {
    std::lock_guard<std::mutex> lock(queue_mutex);
    if(full() || interrupt_flag) return false;
    queue.push(event);
    queue_not_empty.notify_one();
    return true;
  }
  std::optional<T> try_pop() {
    std::lock_guard<std::mutex> lock(queue_mutex);
    if(empty() || interrupt_flag) return std::nullopt;
    T val=queue.front();
    queue.pop();
    queue_not_full.notify_one();
    return val;
  }
  bool push(const T& element) {
    std::unique_lock<std::mutex> lock(queue_mutex);
    queue_not_full.wait(lock,[this](){
        return interrupt_flag || !full();
    });
    if(interrupt_flag) return false;
    queue.push(element);
    queue_not_empty.notify_one();
    return true;
  }
  std::optional<T> pop() {
    std::unique_lock<std::mutex> lock(queue_mutex);
    queue_not_empty.wait(lock,[this](){
        return interrupt_flag || !empty();
    });
    if(interrupt_flag) return std::nullopt;
    T val=queue.front();
    queue.pop();
    queue_not_full.notify_one();
    return val;
  }
  size_t length() {
    std::lock_guard<std::mutex> lock(queue_mutex);
    return queue.size();
  }
 private:
  bool full() {
    return queue.size()>=capacity;
  }
  bool empty() {
    return queue.empty();
  }
  size_t capacity;
  std::atomic<bool> interrupt_flag;
  std::queue<T> queue;
  std::mutex queue_mutex;
  std::condition_variable queue_not_full;
  std::condition_variable queue_not_empty;
};

int main() {
    SyncQueue<int> q(3); // 队列最大容量3

    // 生产者线程：往队列放数字
    std::thread producer([&q](){
        for(int i=1;i<=5;i++){
            bool ok = q.push(i);
            if(!ok) break;
            std::cout<<"生产者放入:"<<i<<"\n";
            std::this_thread::sleep_for(std::chrono::milliseconds(800));
        }
    });
    // 消费者线程：取出数字
    std::thread consumer([&q](){
        while(true){
            auto res = q.pop();
            if(!res.has_value()) break;
            std::cout<<"消费者取出:" << res.value() <<"\n";
            std::this_thread::sleep_for(std::chrono::milliseconds(1000));
        }
    });

    std::this_thread::sleep_for(std::chrono::seconds(6));
    q.interrupt(); // 中断队列，结束线程
    producer.join();
    consumer.join();
    return 0;
}
```

运行现象： 队列容量3，生产者放1,2,3之后队列满，第4次push会**阻塞等待**；消费者慢慢消费，取出元素，队列有空位，生产者才能继续放4、5。调用interrupt之后pop/push返回false/nullopt，线程退出。

## 5. 常见坑（面试常问）

1. 不加锁直接读写queue → 数据竞争，UB未定义行为；
2. wait不带lambda条件，只单纯wait，会被虚假唤醒，逻辑出错；
3. notify_one和notify_all用错场景；
4. 析构忘记唤醒等待线程，线程卡死（死锁）；
5. full/empty无锁访问size，存在数据竞争；
6. 中断标记必须在wait条件里判断，保证中断能唤醒所有阻塞线程。

## 6. 和计算机系统/操作系统的对应知识点

操作系统课程《计算机系统实战》这块对应的概念：

1. 临界区：上锁包裹的代码，操作共享队列的代码就是临界区；
2. 互斥：mutex实现同一时间一个线程进入临界区；
3. 条件同步（同步不等于互斥）：条件变量实现线程等待某个状态；
4. 生产者消费者问题：经典同步问题，有界缓冲区；
5. 阻塞/非阻塞API：push阻塞，try_push非阻塞；
6. 虚假唤醒：操作系统底层特性，wait必须搭配判断条件；
7. 原子变量：atomic，无锁同步基础。
